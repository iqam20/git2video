# storyboard-guide.md — how to author storyboard.json

The renderer takes ONE file: `storyboard.json`. It is generated by the agent
(you) from `story.json` (collect.mjs output). Rules enforced by `validate.mjs`
are marked **(validated)**.

## Top level

```json
{
  "meta":  { "repo": "acme/widget", "label": "v1.4.0", "theme": "dark", "preset": "16:9", "fps": 30 },
  "scenes": [ { ... }, ... ]
}
```

- `meta.repo` + `meta.label` required **(validated)**. `theme`/`preset`/`fps`
  are defaults; `render.mjs --preset/--theme/--fps` override them.
- `scenes` is a non-empty array ordered as the film plays. First scene = `title`,
  last = `outro` **(validated)**. Total 15–75s **(validated, --min/--max to widen)**.

## Every scene

```json
{ "id": "s-title", "type": "title", "duration": 3.5,
  "narration": "One or two sentences.",
  "source": "1a2b3c4, 5d6e7f8",
  "data": { } }
```

| field | rule |
|---|---|
| `id` | unique string, non-empty **(validated)** |
| `type` | one of: title, highlights, diff, stats, timeline, breaking, contributors, outro **(validated)** |
| `duration` | number 0.8–15.0 seconds **(validated)** |
| `narration` | ≤ 2 sentences, ≤ 0.35s/word reading time in the slot; burned as captions **(validated)** |
| `source` | ≥ 1 commit sha; with `--story` every sha must exist in story.json **(validated)** |
| `data` | type-specific object below **(validated)** |

## Scene data shapes

### title (scene 1)
```json
{ "label": "v1.4.0", "repo": "acme/widget", "tagline": "fast builds, smaller output", "date": "2026-11-08" }
```
`label` required ≤40. Visual: repo kicker, big label, gradient underline.

### highlights
```json
{ "items": [
  { "type": "feat",  "text": "session-wide search across tabs" },
  { "type": "fix",   "text": "crash when closing pinned tab on Wayland" },
  { "type": "perf",  "text": "startup 38% faster after bundle split" }
] }
```
1–8 items; `type` ∈ feat|fix|perf|removed|docs|tests|build|changed; text ≤160.
Pick the genuinely important stories; drop trivia.

### diff
```json
{ "file": "src/session.rs", "sha": "1a2b3c4",
  "code": "@@ -120,7 +120,10 @@\n+let pool = build_pool(cfg)?;\n+pool.warm()?;\n-let pool = build_pool_unchecked();" }
```
`file`+`sha`+`code` required; ≤18 lines, each ≤72 chars **(validated)**. Use the
`diffs[]` hunks from story.json (they are pre-sanitized and secret-scrubbed);
wrap/truncate code yourself, never re-read the repo for more code.

### stats
```json
{ "commits": 24, "files": 31, "additions": 1820, "deletions": 217, "contributors": 5 }
```
`commits` required ≥0; count-up animation is automatic.

### timeline
```json
{ "points": [
  { "date": "2026-10-14", "label": "renderer rewrite started" },
  { "date": "2026-10-27", "label": "first 4x build win" },
  { "date": "2026-11-05", "label": "release candidate" }
] }
```
2–6 points: `date` YYYY-MM-DD, `label` ≤60 chars.

### breaking
```json
{ "items": [ { "summary": "config.sample changed schema", "action": "regenerate your config" } ] }
```
1–3 items, summary ≤120, `action` optional ≤120. Only when story.json breaking[] exists.

### contributors
```json
{ "names": ["Ada Lovelace", "Grace Hopper"] }
```
1–12 names. ONLY if collect ran with --include-contributors (names only, never emails).

### outro (last)
```json
{ "headline": "Try it on your repo", "cmd": "npx skills add you/git2video", "url": "github.com/you/git2video" }
```
headline/cmd/url all optional ≤80; cmd gets a terminal box, url a mono footnote.

## authoring recipes

- **30s standard**: title 3.5 / highlights 6 / diff 6.5 / stats 4.5 / breaking 4.5? / outro 3.5 — drop breaking if nothing breaking.
- **15s teaser**: title 2.5 / highlights 4 / stats 3.5 / outro 2.5.
- **45s deep**: add timeline 5 + second diff 6.
- Narration beats visuals: one thought per scene; the caption carries detail.
